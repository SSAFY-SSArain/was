# 🧠 SSArain: 집단지성 기반의 계층형 지식 공유 플랫폼

본 프로젝트는 사용자의 자발적 참여와 AI 기술을 결합하여 지식의 축적 및 학습 효과를 극대화하는 계층형 지식 공유 플랫폼입니다.

## 1. 프로젝트 개요

### 1.1 프로젝트 소개

본 서비스는 단편적인 정보 공유를 넘어, 지식을 유기적인 네트워크 형태로 구조화하고 학습하는 **참여형 지식 생태계 플랫폼**입니다.

사용자는 핵심 단위인 'Neuron'을 통해 지식을 기여하고, 이는 'Topic'과 'Brain'이라는 계층적 구조로 수집·통합됩니다. 플랫폼 내 축적된 데이터는 AI 기반 퀴즈 시스템과 결합하여 사용자에게 단순한 조회를 넘어선 능동적 학습 경험을 제공합니다.

---

### 1.2 기획 배경

- **지식 파편화와 휘발성:**  
  현대 조직 및 부서, 학급 단위에서 발생하는 정보는 메신저, 개인 메모, 산발적인 게시글 형태로 공유되어 시간이 흐름에 따라 빠르게 휘발되고 파편화됩니다. 검색과 재사용이 어려운 기존 게시판 형태의 한계를 극복할 구조적 대안이 필요합니다.

- **학습(조회)과 검증(평가)의 단절:**  
  기존의 지식 공유 플랫폼은 정보를 '읽는' 행위에 치우쳐 있어, 사용자가 내용을 실제로 이해하고 내재화했는지 확인하기 어렵습니다. 지식의 습득과 자가 점검(학습 효율화)이 유기적으로 연결된 시스템이 요구됩니다.

- **소외되는 집단지성과 폐쇄성:**  
  커뮤니티나 반(Class) 단위로 축적되는 지식은 조직의 경계를 넘지 못하고 갇히는 경향이 있습니다. 개별 소그룹의 독립성을 보장하면서도, 필요에 따라 이를 거시적으로 통합하여 거대한 지식 자산으로 전환할 수 있는 유연한 아키텍처가 부재했습니다.

---

### 1.3 핵심 가치 및 목표 (Key Values & Goals)

- **지식의 구조화 및 자산화**:  
  개별 게시글을 계층형 노드로 관리하여 파편화되는 지식을 체계적인 자산으로 축적합니다.
- **높은 재사용성과 편의성**:  
  전역(Global)으로 공유되는 지식 주제(Topic) 시스템을 통해 데이터 파편화를 방지하고 관리 효율을 높입니다.
- **능동적 학습 환경 제공**:  
  AI 기술을 활용한 토픽 단위 퀴즈(Quiz) 생성을 통해 지식 습득의 효율성을 극대화합니다.
- **집단지성의 무한한 확장**:  
  소그룹(Brain) 단위를 넘어 메가 그룹(병합 Brain)으로의 융합을 지원하여 지식의 시너지를 창출합니다.

---

### 1.4 서비스 아키텍처 및 핵심 도메인 모델 (Domain Model)

서비스 내 지식과 그룹은 다음과 같은 계층 구조를 가집니다.

```
[ Brain (그룹/클래스) ]
     └── [ Topic (지식 주제 - 전역 공유) ]
              ├── [ Neuron (개별 게시글) ]
              └── [ Quiz (AI 기반 토픽별 퀴즈 세트) ]

```

#### 1.4.1 지식 및 그룹 엔티티 정의

- **Neuron (뉴런)**: 지식 공유의 가장 최소 단위이자 개별 게시글입니다. 사용자의 경험과 지식이 기록되는 곳입니다.
- **Topic (토픽)**: 여러 Neuron이 모여 이루는 상위 지식 그룹(주제)입니다.
- **전역 공유성**: 서비스 내 모든 Topic은 전역에서 공유 및 재사용되며, 명칭의 통일성을 유지합니다.
- **노출 제어**: 각 Brain은 전역 Topic 중 필요한 토픽만 선택하여 화면에 노출(표시/숨김)할 수 있어 사용자 피로도를 낮춥니다.

- **Quiz (퀴즈)**: 학습 보조를 위한 AI 기반 퀴즈 세트입니다.
- 개별 Neuron 단위에서는 생성·조회가 불가능하며, **Topic 단위로 묶어 일괄 생성 및 조회**합니다.

- **Brain (브레인)**: 여러 Topic이 모여 구성되는 사용자 그룹(반/클래스 개념)입니다.

---

### 1.5 권한 체계 (User Roles & Permissions)

사용자의 역할은 총 5단계로 구분되며, 각 역할에 따른 권한 범위는 다음과 같습니다.

| 권한명            | 정의                   | 주요 권한 범위                                                                                       |
| ----------------- | ---------------------- | ---------------------------------------------------------------------------------------------------- |
| **ADMIN**         | 서비스 최고 관리자     | 서비스 전체 운영 관리, **Brain 병합(통합 Brain 생성)** 권한                                          |
| **BRAIN_ADMIN**   | Brain 개별 최고 관리자 | Brain 생성 시 자동 부여. Brain 정보 수정, 멤버 관리(추가/퇴출/가입 승인), 권한 변경, Topic 노출 관리 |
| **BRAIN_MANAGER** | Brain 보조 관리자      | BRAIN_ADMIN이 지정. 일부 핵심 기능을 제외한 Brain 관리 기능 수행                                     |
| **USER**          | 일반 사용자            | 소속 Brain 내 Neuron 작성, 타 Brain 조회 및 댓글 참여, Topic별 Quiz 풀이, 타 Brain 가입 신청         |
| **GUEST**         | 비회원 / 미인증 사용자 | 지식 개체(Brain, Topic, Neuron, Quiz) 조회 가능, 모든 생성/수정/작성 기능 제한                       |

---

### 1.6 핵심 프로세스 및 기능 (Core Features)

#### 1.6.1 사용자 지식 활동 및 교류

- **활동 및 기여**: 사용자는 소속된 Brain의 특정 Topic 아래에 Neuron을 작성하여 지식을 축적합니다.
- **크로스 브라우징 및 교류**: 소속되지 않은 다른 Brain의 지식도 자유롭게 탐색할 수 있으며, 댓글을 통해 의견을 교환하고 Topic 단위 퀴즈를 풀며 함께 학습합니다.

#### 1.6.2 Brain 관리 및 Topic 큐레이션

- **Brain 생성**: 누구나 Brain을 개설하여 관리자(BRAIN_ADMIN)가 될 수 있습니다.
- **필터링 기반 큐레이션**: 관리자는 전역에 이미 존재하는 Topic을 검색하여 자신의 Brain에 등록하거나, 없을 경우 새로 생성하여 기여할 수 있습니다. 불필요해진 Topic은 숨김 처리하여 Brain을 정제된 상태로 유지합니다.

#### 1.6.3 AI 기반 지식 추출 및 학습 보조

- **Quiz 생성**: 사용자들이 특정 Topic 내에 축적한 다양한 Neuron을 기반으로 AI가 분석·융합하여 학습 퀴즈를 생성합니다.
- **학습 보조**: 사용자는 작성한 지식들이 녹아들어 있는 퀴즈를 풀며 본인의 이해도를 스스로 점검할 수 있습니다.

#### 1.6.4 지식의 융합: Brain 병합 (Brain Merge)

- **목적**: 시간이 흐름에 따라 파편화되거나 기수별/반별로 나뉜 지식 집합을 하나로 통합하여 거대한 지식 베이스를 구축합니다.
- **작동 방식**: 최고 관리자(ADMIN)는 특정 조건(예: '2026년 기준 각 반들의 지식 집합')을 지정하여 여러 Brain을 묶은 '병합 Brain'을 생성할 수 있습니다.
- **사용자 경험**: 병합 Brain은 일반 Brain과 동일한 UX로 조회되며, 사용자는 소속 경계를 넘어 융합된 거대 집단지성을 자유롭게 탐색하고 학습할 수 있습니다.

### 1.7 실행 참고사항

#### 1.7.1 프론트

- 현재 프론트 페이지에서 API 요청을 전송하는 위치가 배포 서버 주소로 설정되어 있습니다.
- 로컬에서 서버를 구동하는 경우, `frontend/vite.config.js` 내 `target:` 값을 변경해주세요.

#### 1.7.2 백엔드

- **DB 서비스 의존성**
  - 백엔드 애플리케이션은 구동을 위해 Redis(또는 Valkey), MySQL 서비스를 요구합니다.
  - `backend/docker`의 서비스를 활용해도 무방합니다.  
    (이 경우 Docker 환경 필요)
- **AI API 의존성**
  - 퀴즈 기능을 위해 AI API가 연결되어야 합니다.
  - 환경변수 등을 통해 API 키를 등록해주세요.

## 3. 서버 아키텍쳐

- **서버 환경**
  - AWS 기반 웹 클라우드 서비스를 활용합니다.
  - EC2: 웹 애플리케이션 및 메모리 캐시를 구동합니다.
  - RDS: 메인 DB 서비스를 구동합니다.
- **CI/CD**
  - Github에서 제공하는 Github Actions 기능을 기반으로  
    CI + CD 파이프라인을 구축합니다.
- **Docker**
  - Valkey, Spring, 프론트 서비스 등 서비스 단위 별로 배포를 용이하게 하기 위해  
    Docker Container 형태로 이미지화 해 운영 환경으로 배포합니다.
